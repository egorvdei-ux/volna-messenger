# Волна — первая версия мессенджера

**Статус:** iOS-приложение успешно скомпилировано Xcode на облачном Mac, настоящий `Volna-unsigned.ipa` скачан в папку результатов этого чата. Проверены структура IPA, контрольные суммы архива и исполняемый ARM64 Mach-O для iPhone. Минимальная версия — iOS 17. Файл пока не подписан и на телефон НЕ установлен.

[Успешная облачная сборка](https://github.com/egorvdei-ux/volna-messenger/actions/runs/41595202486), исходный коммит `b6c8016f1d85d50670dcc96e710a9a562faa83ee`. SHA-256 IPA: `c71f7714ca9baaa4e9df4c1554cee771f8ec1f38a1b520105ea15499169acea5`.

## Что есть

- iPhone/iPad, iOS 17 и новее: интерфейс на SwiftUI, тёмная тема, мятный акцент.
- Регистрация по имени пользователя и паролю, вход и выход.
- Личные диалоги по имени пользователя; собеседник должен зарегистрироваться на том же сервере.
- Текст и эмодзи, история, загрузка предыдущих сообщений, обновление примерно каждые 2 секунды при открытом приложении.
- Повторная отправка после ошибки без дублей, если исходное сообщение уже дошло до сервера.
- Сервер на Node.js 24+ без сторонних npm-зависимостей; база SQLite сохраняется на ПК.
- Браузерный клиент для ПК и Safari, чтобы проверить обмен сообщениями до сборки iOS.

Звонков, вложений, push-уведомлений, индикаторов прочтения и сквозного шифрования в этой версии нет. Галочка у сообщения означает приём сервером. Сервер видит содержимое сообщений. При использовании локального HTTP сетевой трафик не зашифрован. Это первая версия для своей сети, а не готовый публичный сервис.

## Попробовать сейчас на Windows и iPhone

1. Дважды нажмите `Start-Server.cmd`. Нужен Node.js 24+; на этом ПК скрипт также умеет находить встроенный Node.js из Codex. Если сервер уже работает, второй экземпляр не нужен.
2. Оставьте окно сервера открытым. На ПК откройте <http://localhost:8787>.
3. Подключите iPhone к той же Wi-Fi сети, что и ПК. В Safari откройте **<http://192.168.0.19:8787>**. Этот адрес определён для текущего ПК; при смене сети он может измениться. Актуальные адреса сервер печатает при запуске. Подключение по USB сеть Wi-Fi не заменяет.
4. Создайте свой аккаунт. Для проверки создайте второй аккаунт в другом браузере, приватном окне или на втором телефоне. В браузере вход хранится отдельно для каждой вкладки.
5. Нажмите `+` и введите имя пользователя собеседника. Оба должны использовать один и тот же сервер.

Если телефон не открывает страницу: проверьте Wi-Fi, адрес, работу сервера и изоляцию устройств на роутере. VPN может мешать доступу к локальной сети. Если Windows блокирует Node.js, разрешите входящие подключения для него только в своей частной сети. Настройки брандмауэра автоматически не изменялись.

Данные: `server/data/volna.sqlite` и файлы SQLite рядом. Не удаляйте их, если нужна история. Для резервной копии остановите сервер и скопируйте весь каталог `server/data`. Базу и сессии не следует загружать в GitHub. В архив исходников данные пользователей не включены.

## Как повторно собрать IPA без своего Mac

Первую сборку уже выполнил этот чат. Следующие шаги нужны для повторения сборки или переноса проекта; готовый файл можно взять из результатов чата либо из Artifacts успешного запуска выше.

Понадобится аккаунт GitHub и доступный ему запуск GitHub Actions на macOS. Возможность и стоимость зависят от лимитов аккаунта; архив не запускает платную сборку автоматически.

1. Создайте пустой репозиторий, предпочтительно приватный.
2. Загрузите **содержимое** папки `Volna` в корень репозитория, включая `.github/workflows/ios.yml`, `ios`, `scripts` и `server`. Сам ZIP не является исходным репозиторием для Actions. В Windows папку `.github` иногда удобнее загрузить через GitHub Desktop.
3. Откройте вкладку **Actions → Build iPhone IPA → Run workflow**. Сборка также запускается при изменениях в ветках `main` или `master`.
4. Дождитесь успешного выполнения серверных тестов и задания `build-ios`. В случае ошибки смотрите журнал.
5. В разделе **Artifacts** скачайте `Volna-unsigned-IPA` и распакуйте ZIP. Внутри будет **Volna-unsigned.ipa** с исполняемым файлом для ARM64 iPhone.

Это неподписанный IPA. До подписи он не установится на обычный iPhone. Сценарий использует настоящий `xcodebuild` на macOS, а затем упаковывает `Payload/Volna.app`; он не переименовывает исходники в IPA.

## Установка собранного IPA с Windows

Один из вариантов — [Sideloadly с официального сайта](https://sideloadly.io/). Оно умеет подписывать и устанавливать IPA с Windows. Сначала выполните требования к драйверам на официальном сайте; установщик в комплект не входит.

1. Подключите разблокированный iPhone по USB и подтвердите «Доверять этому компьютеру» на телефоне.
2. Откройте Sideloadly и выберите ваш iPhone.
3. Перетащите `Volna-unsigned.ipa` в Sideloadly.
4. Введите свой Apple Account непосредственно в Sideloadly и выполните подпись/установку. Не отправляйте пароль в чат. Приложение «Волна» пароль Apple не запрашивает.
5. Если iOS потребует, включите режим разработчика и подтвердите доверие разработчику в настройках телефона.
6. Откройте «Волна». На экране входа укажите адрес работающего сервера ПК, например `http://192.168.0.19:8787`.

По [FAQ Sideloadly](https://sideloadly.io/faq), подпись бесплатного Apple Account обычно действует 7 дней и требует обновления. Фактическую совместимость с вашей версией iOS и успешность подписи здесь проверить не удалось.

## Если появится Mac

Установите полный Xcode с iOS SDK, откройте `ios/Volna.xcodeproj`, выберите Team в Signing & Capabilities и подключённый iPhone. Нажмите Run. При необходимости смените Bundle Identifier на уникальный. Xcode создаёт профиль подписи для вашего аккаунта.

Для неподписанного IPA на Mac:

```bash
bash scripts/build-ipa.sh
```

Результат: `dist/Volna-unsigned.ipa`.

## Проверка и ограничения

```powershell
node --test server/test.mjs
```

В этом чате успешно прошли 7 интеграционных тестов: обмен двух пользователей и изоляция чатов, защита от дублирования, вход/выход, валидация, страницы истории, сохранение после перезапуска и загрузка браузерного клиента. В отдельной тестовой базе через браузер вручную проверены регистрация двух пользователей, создание диалога и обмен сообщениями в обе стороны. Ошибок в консоли браузера при этой проверке не было.

Компиляция Swift/Xcode и создание IPA успешно прошли в GitHub Actions; серверные тесты также прошли в облаке. Локально проверены CRC архива, Info.plist (iPhoneOS, iOS 17), заголовок ARM64 Mach-O и отсутствие подписи/профиля. Подпись, установка, запуск iOS-приложения и доступ из Safari на физическом телефоне здесь **не проверены**. Проверка браузера на размере 390×844 пройдена; это не проверка нативного интерфейса на устройстве.

Сервер слушает порт `8787` на сетевых интерфейсах. Для другого порта задайте переменную `PORT`. Для другой базы — `VOLNA_DATABASE`. Для доступа только с этого ПК — `HOST=127.0.0.1`. Подключения по USB автоматически не используются.

Для работы через интернет понадобится отдельный сервер с HTTPS, резервным копированием и дополнительной эксплуатационной защитой. Не открывайте порт этой тестовой конфигурации в интернет. В iOS-клиенте HTTP разрешён только для локальных адресов; URL внешнего сервера должен начинаться с HTTPS.

Токен iOS хранится в Keychain, токен браузера — в sessionStorage. Сервер хранит хеши токенов, а пароли — в виде scrypt-хешей с солью. Сессии истекают через 30 дней. При выходе без связи удаляется локальный вход, но серверная сессия остаётся до истечения срока. Защита от перебора и ограничения запросов базовые.

## Структура

```text
ios/                  SwiftUI и проект Xcode
server/server.mjs     HTTP API и SQLite
server/public/        тестовый клиент для Safari и ПК
server/test.mjs       интеграционные тесты
scripts/build-ipa.sh  сборка на Mac
.github/workflows/    облачная сборка на GitHub Actions
Start-Server.cmd      запуск сервера на Windows
```
